# 织影系统 (Loom System) - 面试与应答策略

## 1. 核心技术选型话术

| 技术模块 | 考点 (Why) | 回答策略 (How to Pitch) |
| :--- | :--- | :--- |
| **LangGraph Supervisor** | 复杂编排、循环自省 | "我用 Supervisor + Conditional Edges 做中央协调，分镜 JSON 校验失败会自动重写最多 3 轮，再降级至模板兜底，重试成功率 >99%。" |
| **asyncio vs Celery** | 并发架构决策理性 | "MVP 用 asyncio + Semaphore 限流，避免 Celery 运维负担；扩容时平滑切换 Celery，两层设计互不耦合。" |
| **成本熔断器** | 企业级成本控制 | "State 内置 cost_accumulator，每次 API 调用实时累加费用，达到阈值自动挂起管线——这不是事后统计，是实时刹车。" |
| **Task Classifier** | 模型路由智能化 | "不是简单的 if-else，而是基于文本长度、是否涉及角色描写、是否需要视觉生成三个维度的规则引擎，自动路由至 Ollama 或云端。" |
| **双层 RAG 分片** | 幻觉解决方案 | "章节级粗切做上下文窗口，角色实体级细切做视觉档案——同一主角在第 1 章和第 50 章的外貌描述都在同一个向量集合中，检索即一致。" |
| **FFmpegAssembler** | 工程落地能力 | "每个视频片段进来先做分辨率/帧率/编码归一化检测，不一致的自动转码后再拼接——这是很多人忽略但生产必崩的细节。" |
| **PostgreSQL RLS** | 多租户安全 | "行级安全策略隔离不同用户数据，配合 Thread ID 实现真正的 SaaS 级别的数据互不可见。" |
| **Checkpointer 断点续跑** | 系统韧性 | "Kling 生成一个镜头 ¥5-20，宕机后从 Checkpoint 继续，不浪费已生成的昂贵视频素材。" |

## 2. 关键"杀手锏"级话术

1.  **"实时成本熔断，不是事后账单"**：
    > "传统方案是 LangSmith 统计完了再看花了多少钱——我的方案是 State 内嵌累加器，跑到 ¥500 自动暂停。这才是真正的成本控制。"

2.  **"角色记忆：查一次，用一路"**：
    > "首次 RAG 查完角色档案后直接写入 State 缓存，同一任务后续所有镜头直接复用——零延迟且保证一致性。"

3.  **"asyncio 是理性选择，不是偷懒"**：
    > "个人项目引入 Celery 是过度工程。asyncio Semaphore 在单机能撑 50+ 并发。等真正需要多机器分发时，集成 Celery 只需改一层抽象接口。"

4.  **"分镜自省三轮兜底"**：
    > "Pydantic 校验失败不是报错退出，而是带着错误信息重新调用 LLM 修正，最多 3 轮。3 轮还不行就降级到预定义模板——管线永不中断。"

## 3. 常见追问应对

| 追问 | 回答要点 |
| :--- | :--- |
| "为什么不用 CrewAI？" | "CrewAI 适合简单的角色扮演场景；织影系统需要条件分支、循环自省、断点续跑和 HITL 中断——这些只有 LangGraph 的有向图才能精确控制。" |
| "ChromaDB 能撑多大规模？" | "MVP 验证用。生产环境切 Milvus 集群，支撑百万级向量。接口层做了抽象，切换只改一个 Config。" |
| "如果 Kling API 挂了怎么办？" | "三层防护：① 指数退避重试 ② 多 API Key 轮换 ③ Fallback 到 Runway Gen-4。Supervisor 自动决策，无需人工干预。" |
| "Streamlit 能支撑多人审批吗？" | "MVP 够用。已在 Sprint 4 预研 FastAPI WebSocket 方案，多人审批通过 WebSocket 实时推送。" |
| "怎么保证输出 JSON 格式正确？" | "Pydantic BaseModel 做 schema 强约束 + Function Calling 引导输出格式 + 循环自省纠错。三层保障。" |
